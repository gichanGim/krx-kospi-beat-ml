## 2. 데이터 수집

### 2.1 설계
- **단면 데이터 한 시점**: 기준일 D = 2024년 12월 마지막 거래일(실제 조회되는 날짜로 확정, 보통 12/30). 특성 = D 시점 지표. 레이블 = D ~ 2025년 12월 마지막 거래일 수익률이 같은 기간 코스피 지수 수익률보다 크면 1("코스피 초과"), 아니면 0("코스피 미달").
- 행: 코스피+코스닥 보통주 약 2,000~2,500개. 열: PER, PBR, DIV(배당수익률), EPS, BPS, 시가총액, 거래대금, 시장(KOSPI/KOSDAQ), 업종.
- **양성(찾으려는 대상) = 1 = 코스피 초과.** 사이킷런 기본 `pos_label=1`과 일치. 지표 값을 적을 때마다 "코스피 초과를 양성으로 놓고 임계값 0.5에서 재 정밀도 0.xxxx" 형식으로 기준을 함께 적는다(Ch04 규칙).
- 두 번째 시점(2023년 말→2024)은 선택. 쓰면 "2023 단면으로 학습한 모델을 2024 단면에 적용" = 슬라이드 23 "앞을 훈련, 뒤를 테스트" 확인 → 4장 끝이나 5장에.

### 2.2 수집 경로 (우선순위)
**A. pykrx** (`from pykrx import stock`; README에서 확인한 함수, 세부는 실행해서 확인)
- `stock.get_market_fundamental_by_ticker("20241230", market="KOSPI")` → BPS, PER, PBR, EPS, DIV. `market="ALL"` 동작 여부 [확인 필요], 안 되면 KOSPI·KOSDAQ 따로 받아 `pd.concat`.
- `stock.get_market_cap_by_ticker("20241230", market=...)` → 시가총액, 거래량, 거래대금, 상장주식수.
- `stock.get_market_price_change_by_ticker("20241230", "20251230", market=...)` → 등락률(1년 수익률). 수정주가 반영 여부 [확인 필요].
- `stock.get_index_ohlcv_by_date("20241230", "20251230", "1001")` → 코스피 지수(코드 1001 여부는 `get_index_ticker_list()`로 확인).
- 호출은 시점당 5~6회뿐. 종목별 반복 호출(2,500회) 금지(README: 차단 위험).

**B. KRX 정보데이터시스템(data.krx.co.kr) 수동 CSV** — 라이브러리가 깨지면. "PER/PBR/배당수익률(개별종목)", "전종목 등락률", "업종분류현황", "개별지수 시세". `pd.read_csv(path, encoding="cp949", thousands=",", dtype={"종목코드": str})`.

**C. FinanceDataReader** — `fdr.StockListing('KRX')`는 오늘 기준 스냅샷이라 업종·시장 구분용만. `fdr.StockListing('KRX-DELISTING')` 상장폐지 목록. 반환 열은 바뀐 사례가 있으니 `df.columns` 찍어 확인.

**코랩 주의**: 코랩은 해외 IP라 KRX가 막을 수 있음 [확인 필요]. 막히면 수집만 집 PC에서, CSV만 코랩으로. **분석 노트북은 CSV만 읽게 분리**(교수님 재실행 보장).

### 2.3 수집 순서
1. 지표 표 + 시가총액 표를 종목코드로 `merge`.
2. 업종·시장 표 병합(B 또는 C).
3. 등락률 표로 수익률 → 코스피 수익률 빼서 레이블. 종료일 시세가 없는 종목(상장폐지·거래정지)은 `delisted=1` 표시.
4. 우선주(종목명 끝 "우", 코드 끝자리 ≠ 0)·스팩·리츠 제외, 제외 전후 행 수 기록.
5. `stock_2024.csv` 저장 → 드라이브 + GitHub `data/`. 코스피 수익률은 노트북 마크다운과 `index_return.csv`에 기록.

## 4. 보고서 5장 구성 (본문 5쪽 이상, 목표 6쪽)

파일명 `학번_이름_보고서.pdf`. 표지: 과목명, 학번, 이름, 데이터 이름("한국거래소 코스피·코스닥 상장사 2024년 말 재무지표와 2025년 수익률"). 용어는 교수님 표기(훈련/테스트 데이터, 특성/레이블, 과적합, 데이터 누수, 층화 추출, 빈칸·튀는 값·글자를 숫자로·크기 맞추기, 네 칸, 헛경보/놓침, 기준선, 양성 기준 정밀도·재현율). 모든 지표 값에 "무엇을 양성으로, 어느 임계값에서"를 함께.

### 1장. 무엇을 예측하려 했는가 (약 0.8쪽, 4점)
- 동기 2~3문장(주식이 취미, 공개된 재무지표만으로 시장 평균을 이길 종목을 고를 수 있는가).
- Ch01 틀로 문제 정의: 정답 칸을 과거 데이터로 만들 수 있다 → 지도학습; 답이 "종류"(초과/미달) → 분류, 그중 이진 분류. 수익률(숫자, 회귀)을 "코스피 초과 여부"(종류)로 바꾼 이유: 절대 수익률은 그 해 시장 방향에 묻혀 지표 효과가 안 보임.
- 출처와 주소(KRX, pykrx/FDR GitHub), 기준일, 다운로드일. 행·열 수(제외 전/후). **표1 열 설명표**(열 이름, 뜻, 단위, 출처).
- 레이블 정의식과 2025년 코스피 수익률 값, `np.bincount` 결과(1의 비율). **그림1** 레이블 분포 막대.

### 2장. 데이터를 어떻게 다듬었는가 (약 1.3쪽, 4점) — Ch02 점검표 순서로
- **살펴보기**: `shape`·`dtypes`, 빈칸 비율표(**표2**), describe에서 평균≫중앙값인 열(시가총액·거래대금·PER). "무엇을 보고 그렇게 판단했는지" 문장.
- **나누기**: `stratify=y`, `random_state=42`, 전체/훈련/테스트 비율 세 숫자. 시계열 누수 질문에 답: "특성은 전부 같은 날짜 값이고 레이블 기간도 같아 행을 섞어도 미래 정보가 과거로 가지 않는다. 다만 한 해의 시장 분위기를 양쪽이 공유하므로 '다른 해에도 통하는가'는 별도 확인(7.8 또는 5장)". 같은 종목이 양쪽에 없음(그룹 누수 없음). 특성 중 "예측 시점에 알 수 없는 값"이 없는지 하나씩 확인했다는 문장.
- **빈칸**: PER 빈칸 = 적자 기업 → "빈칸 자체가 정보" → 중앙값(훈련에서 구한 값 명시) + 표시 열. 채우기 전후 표준편차 변화("공짜가 아님"). DIV 0은 무배당이지 빈칸이 아님.
- **튀는 값**: 훈련 데이터 IQR 건수와 비율, 상위 3개 값을 열어 본 결과(대형주·고PER 성장주 = 실제 값) → 지우지 않음. 시가총액·거래대금 로그 변환(**그림2** 전후 히스토그램). PER·PBR 처리와 이유. "지우면 무엇을 잃는가"를 초과 비율로 확인.
- **글자를 숫자로**: 시장 2값, 업종 n개(빈도 20 미만 "기타" 묶음) 원핫, reindex로 훈련·테스트 열 일치(열 개수).
- **크기 맞추기**: Pipeline(impute→scale) 훈련에서만 fit. 로지스틱만 표준화, 숲은 "값의 순서만 쓰므로" 불필요. 검산 수치(훈련 0·1 정확히, 테스트 근처) 문장으로. **표3** 전처리 전후 범위 비교. 가능하면 **표 2-2 형식**: 같은 로지스틱에 표준화 전/후 정확도.
- 단계별 행 수 변화표(원본→우선주·스팩 제외→상장폐지 처리→최종).

### 3장. 어떤 모델을 왜 골랐는가 (약 1쪽, 4점)
- 후보표(**표4**): 로지스틱 회귀·결정트리·랜덤포레스트·(이름만) 부스팅·신경망·K-평균/PCA — 각 한 줄 + 선택 여부.
- 고른 이유(Ch05·Ch07 문장): "모델은 매개변수 모델(로지스틱, 표준화 필요, 직선 경계, 계수로 설명)과 비매개변수 모델(트리, 표준화 불필요, 계단 경계)로 갈림" / "데이터를 보기 전에 최고의 모델을 정할 수 없어 후보 몇 개를 검증 성능으로 고르는 것이 표준 절차" / "표 형태 데이터에서는 앙상블이 표준" / "금융은 설명을 못 하면 도입이 막힘 → 계수와 규칙을 읽을 수 있는 모델". 결정트리 하나가 아니라 숲인 이유(데이터가 조금 바뀌면 나무가 달라짐, 배깅이 분산을 줄임). 신경망을 안 쓴 이유: "특성 수십 개짜리 표 데이터에서는 신경망이 로지스틱보다 낫지 않았음(수업 0.9825 vs 0.9561), 은닉층 값은 해석 어려움". 군집화·PCA는 "정답이 있으면 정답을 쓰는 편이 언제나 나음", "새 축에는 이름이 없어 설명 자리에서 불리".
- 정한 값: `LogisticRegression(max_iter=1000)`(기본 100은 수렴 경고), `RandomForestClassifier(n_estimators=100, random_state=42)` + for 루프 결과(**표5** 깊이/그루 수별 훈련·테스트) + 교차검증 평균±표준편차(**표6**) → "검증 점수로 골랐고 테스트는 마지막에 한 번".
- 기준선(다수 클래스)을 함께 두는 이유.

### 4장. 결과를 어떻게 읽었는가 (약 1.8쪽, 5점) — 소제목을 5단계 그대로
1. **클래스별 개수와 혼동행렬(진단)**: 테스트 표본 수와 1의 비율, "한 건 = 1/N". **그림3** 두 모델 혼동행렬 네 칸(각 칸에 "미달을 초과라 함(헛경보)" 식 이름). 기준선 정확도 vs 두 모델 정확도.
2. **어느 실수가 더 비싼가(판단)**: 상황 가정을 명시. "이 모델을 매수 후보 선별에 쓴다고 하면 헛경보(FP: 미달 종목을 초과라 함)는 실제 손실, 놓침(FN)은 기회비용 → 헛경보가 더 비싸다 → 정밀도를 먼저 본다." 반대 상황(1차 스크리닝 후 사람이 검토 → 놓침이 비싼 → 재현율)도 표 4-32 형식(**표7**: 가장 비싼 틀림 / 올리고 싶은 값 / 고를 임계값 / 그때의 값 / 감수하는 것 / 전제)으로 나란히.
3. **맞는 지표(선택)**: 정밀도·재현율·F1(**표8**, 두 모델 + 기준선), 손 계산 대조 한 줄.
4. **임계값 옮겨 보기(조정)**: **그림4** 임계값–정밀도·재현율 두 선(0.5 점선). 0.5와 고른 임계값에서 네 칸이 어떻게 바뀌는지, "임계값은 모델을 좋게 만드는 것이 아니라 두 틀림의 배분을 바꾸는 일". `class_weight="balanced"` 결과(계수 자체가 바뀜 vs 임계값은 계수 불변).
5. **classification_report와 어느 줄을 볼지(보고)**: 두 모델 표 붙이고 "above_kospi 줄의 precision을 본다", 불균형이면 macro avg.
- 이어서 **해석**: **그림5** 숲 특성 중요도 상위 5 + 로지스틱 exp(계수) 상위 5("1 표준편차 커지면 초과 오즘가 x배"). "원인이 아니라 모델이 쓴 정도", 상관 높은 특성끼리 중요도가 나뉨 경고. **표9** 틀린 종목(헛경보 상위 10·놓침 상위 10)의 업종·시총 공통점. 훈련 vs 테스트 정확도로 과적합 판정(숲 훈련 1.0 = 암기).
- 성능이 낮아도 되는 근거: 기준선과 얼마나 다른지 숫자로, 효율적 시장(공개 지표는 이미 가격에 반영), 연 1회 지표의 시차, 레이블 잡음. "낮은 성능 + 이유 설명"이 채점 기준.

### 5장. 아쉬운 점과 다음에 할 일 (약 0.5쪽)
